# disasm — дизассемблер для Emacs

Небольшой пакет на Emacs Lisp, который запускает внешний дизассемблер
(GNU `objdump` или `llvm-objdump`) и показывает дизассемблированный код
в read-only буфере с подсветкой синтаксиса, навигацией по инструкциям,
переходами (`xref`) и индексом функций (`imenu`).

Поддерживаются любые форматы, которые понимает выбранный бэкенд:
PE/EXE, DLL, ELF, Mach-O, объектные файлы — архитектура и формат
определяются автоматически.

Бэкенд выбирается переменной `disasm-backend`:

- `objdump` (по умолчанию) — GNU binutils;
- `llvm-objdump` — LLVM. Его вывод `-h` не содержит файловых смещений
  секций, поэтому пакет дополнительно разбирает таблицу секций PE/COFF и
  ELF, чтобы восстановить смещения для синхронизации hex ↔ дизасм.

## Требования

- Emacs 28.1 или новее.
- GNU `objdump` из binutils (по умолчанию). На этой машине уже есть:
  `C:\cygwin64\bin\objdump.exe`. Путь задаётся в
  `disasm-objdump-program`.
- `llvm-objdump` — только если выбран бэкенд `llvm-objdump`. Путь
  задаётся в `disasm-llvm-objdump-program`.

## Установка

```elisp
(add-to-list 'load-path (expand-file-name "lisp/disasm" user-emacs-directory))
(require 'disasm)
```

Если `disasm-bind-prefix` включён (по умолчанию), команды доступны
через префикс `C-c d`.

## Использование

- `M-x disasm-file` (`C-c d f`) — дизассемблировать файл (одна панель).
- `M-x disasm-buffer` (`C-c d b`) — дизассемблировать файл текущего буфера.
- `M-x disasm-open` (`C-c d o`) — открыть дизассемблер в «докованном»
  режиме (как в x64dbg): листинг сверху слева, hex-панель под ним, а
  справа — колонка из двух панелей: секции сверху, функции снизу.
- `M-x disasm-open-raw` (`C-c d r`) — дизассемблировать «сырой» бинарник
  без заголовка (запрашивает архитектуру и базовый адрес). Поддерживается
  только бэкендом `objdump`; `llvm-objdump` для «сырых» файлов не годится
  и сообщает об ошибке.
- `M-x disasm-open-hex` (`C-c d h`) — открыть hex-панель к текущему
  листингу.
- `M-x disasm-sync-mode` (`C-c d s`) — включить/выключить глобальную
  синхронизацию панелей.
- `M-x disasm-cache-clear` (`C-c d c`) — очистить кэш результатов.

Клавиши в буфере `disasm-mode`:

| Клавиша | Действие                                   |
|---------|--------------------------------------------|
| `n` / `p` | следующая / предыдущая инструкция        |
| `g`     | переход к адресу (в hex)                    |
| `a`     | переход к точке входа (entry point)         |
| `RET`   | перейти по цели прямого `call`/`jmp`        |
| `M-.` / `M-,` | переход по xref и назад                |
| `b`     | показать/скрыть колонку байтов              |
| `D`     | дизассемблировать все секции, а не только код |
| `R`     | обновить                                    |
| `y` / `w` | скопировать адрес / инструкцию            |
| `q`     | закрыть все панели сессии                   |

Клавиши в буфере `disasm-hex-mode`:

| Клавиша | Действие                                   |
|---------|--------------------------------------------|
| `g`     | переход к адресу (hex) / файловому смещению |
| `q`     | закрыть все панели сессии                   |

Боковые панели (`disasm-sections` и `disasm-functions`) открываются
командой `disasm-open`; в них:

| Клавиша | Действие                                   |
|---------|--------------------------------------------|
| `RET` / `mouse-1` | перейти к адресу в листинге       |
| `n` / `p` | следующий / предыдущий элемент           |
| `q`     | закрыть все панели сессии                   |

`imenu` (`M-g i`) содержит группы `Functions` и `Sections`.

## Асинхронная загрузка и кэш

Заголовок и таблица секций читаются сразу (это быстро), а само
дизассемблирование запускается в фоне через `make-process`. Пока идёт
работа, в листинге показывается заглушка «disassembling …», а в
header-line — индикатор `[disassembling ...]`. Emacs остаётся
отзывчивым даже для очень больших бинарников: например, для файла на
~316 000 инструкций открытие возвращает управление меньше чем за
секунду, а результат появляется через ~17 с.

Результаты дизассемблирования кэшируются в памяти. Ключ кэша включает
путь, размер и время изменения файла, а также все параметры, влияющие на
вывод objdump (backend, синтаксис, demangle, доп. аргументы, all-sections,
raw). Поэтому повторное открытие уже разобранного файла и переключение
опций (например, `D`) происходят мгновенно, а изменение файла на диске
автоматически сбрасывает устаревшую запись.

## Синхронизация hex + дизасм

`C-c d o` открывает четыре панели в одном фрейме (раскладка в духе
x64dbg): слева сверху — листинг, под ним — hex; справа — секции сверху
и функции снизу. Пропорции задаются переменными
`disasm-outline-width`, `disasm-hex-height` и `disasm-outline-split`.
Hex-панель показывает файл построчно: колонка файлового смещения,
колонка виртуального адреса (для секций, у которых есть содержимое),
16 байт в hex и их ASCII-представление.

При включённом `disasm-sync-mode`:

- перемещение по листингу прокручивает hex-панель к тому же адресу и
  подсвечивает байты текущей инструкции;
- перемещение по hex-панели прокручивает листинг к ближайшей инструкции
  по соответствующему виртуальному адресу.

Синхронизация привязывается к строке, на которой стоит курсор в активной
панели; вторая панель выравнивается по этому же адресу. Виртуальный адрес
для строк, попадающих в «шапку» файла или в секции без содержимого
(например, `.bss`), не вычисляется, поэтому такие строки в hex-панели не
имеют соответствия в листинге.

## Боковые панели (секции и функции)

Правая колонка «докованной» раскладки показывает две боковые панели.
Верхняя перечисляет секции (имя и виртуальный адрес) сразу после
открытия файла, нижняя — функции (символы) по мере поступления
результата фонового дизассемблирования. `RET` или клик мышью по строке
переводит листинг (и связанную hex-панель) к выбранному адресу.
Локальные метки (имена, начинающиеся с точки) и символы, совпадающие с
именами секций, в списке функций отфильтровываются.

## Настройка (`M-x customize-group RET disasm`)

- `disasm-backend` — какой бэкенд использовать: `objdump` (по умолчанию)
  или `llvm-objdump`.
- `disasm-objdump-program` — путь к GNU objdump.
- `disasm-llvm-objdump-program` — путь к llvm-objdump.
- `disasm-syntax` — `intel` (по умолчанию) или `att`.
- `disasm-demangle` — деманглить C++ имена.
- `disasm-show-bytes` — показывать ли колонку байтов.
- `disasm-disassemble-all` — все секции или только код.
- `disasm-objdump-extra-args` — дополнительные аргументы GNU objdump.
- `disasm-llvm-objdump-extra-args` — дополнительные аргументы
  llvm-objdump.
- `disasm-bind-prefix` — привязывать ли `C-c d`.
- `disasm-cache-enabled` — включён ли кэш результатов (по умолчанию да).
- `disasm-cache-max-entries` — сколько результатов хранить в кэше
  (по умолчанию 8).
- `disasm-raw-arch` — архитектура по умолчанию для `disasm-open-raw`
  (по умолчанию `i386:x86-64`).
- `disasm-raw-base` — базовый адрес по умолчанию для `disasm-open-raw`
  (по умолчанию 0).
- `disasm-fontify-limit` — если инструкций больше этого числа, подсветка
  операндов отключается ради скорости (по умолчанию 40000; `nil` —
  без ограничения).
- `disasm-hex-max-bytes` — предел числа байт, отрисовываемых в hex-панели
  (по умолчанию 64 МиБ; большие файлы обрезаются).
- `disasm-outline-width` — ширина правой колонки (секции/функции) в
  процентах от ширины фрейма (по умолчанию 30).
- `disasm-hex-height` — высота hex-панели в процентах от высоты левой
  колонки (по умолчанию 35).
- `disasm-outline-split` — высота панели секций в процентах от высоты
  правой колонки; панель функций занимает остаток (по умолчанию 40).
- лица `disasm-*-face` для цветов.

## Известные ограничения / дальнейшие шаги

- Отрисовка листинга синхронная и выполняется в главном потоке после
  завершения objdump; для очень больших файлов (сотни тысяч инструкций)
  это заметная задержка. Чтобы смягчить её, при числе инструкций выше
  `disasm-fontify-limit` отключается подсветка операндов.
- Отрисовка hex-панели синхронная (≈2.5 с для файла в 2.5 МиБ);
  планируется отложенная/асинхронная отрисовка.
- Кэш хранится только в памяти и не переживает перезапуск Emacs.
- «Сырые» бинарники поддерживаются через `disasm-open-raw`: objdump
  запускается с `-b binary -m ARCH --adjust-vma=BASE`, создаётся одна
  синтетическая секция `.data`, покрывающая весь файл.
- Бэкенд `llvm-objdump` реализован, но его вывод `-h` не содержит
  файловых смещений секций. Пакет восстанавливает их, разбирая таблицу
  секций контейнера (PE/COFF или ELF). Для «сырых» файлов без заголовка
  восстановить смещения нельзя, поэтому `llvm-objdump` в режиме
  `disasm-open-raw` не поддерживается (используйте GNU `objdump`).
- Разбор таблицы секций PE/ELF читает только заголовки (несколько
  килобайт), поэтому остаётся дешёвым и для больших файлов. Секции без
  содержимого на диске (`.bss` / `SHT_NOBITS`) пропускаются.
- В раскладке `disasm-open` правая колонка показывает секции и функции
  (как замена панелей регистров/флагов/стека из x64dbg): пакет ничего не
  исполняет, поэтому живое состояние регистров и стека недоступно.
